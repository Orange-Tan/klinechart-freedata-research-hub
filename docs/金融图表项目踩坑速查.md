# 金融图表项目踩坑速查（K 线图对比平台实战沉淀）

> **本文档定位**：本项目是「更大金融工具项目」的踩坑预研。这里沉淀了数据源接入、
> 图表库适配、React 工程、测试调试四层踩过的全部坑与解法，以及可直接复用的代码模式。
> **新项目起步先读这里**，按需照抄「可复用模式」，对照「坑位表」规避老坑。
>
> 项目现状：Vite + React 19 + TS（strict）+ Playwright。4 库（Lightweight-Charts /
> klinecharts v10 / HQChart / ECharts）同源喂数据横向对比；5 大市场免费数据源接入与连通性检测。

---

## 0. 一句话总纲（全文浓缩）

1. **统一协议先行**：全项目用 `OHLCV { time(ms), open, high, low, close, volume }` 作中转，
   上游适配器只负责"各源格式 → OHLCV"，图表适配器只负责"OHLCV → 各库 API"，两头互不关心。
2. **时间戳一律 fake-UTC**：上游返回的是交易所壁钟时间字符串，解析时**显式按 UTC 构造**
   （"2026-09-08" → `Date.UTC(...)`），所有图表按 UTC 渲染 → 任何浏览器时区下显示一致，
   4 个库无需各自改时区。**不要用 `new Date(str)` 隐式解析**（不同浏览器对无时区串行为不一致）。
3. **浏览器直连拿不到数据的坑（CORS/坏池/反爬）**：dev 一律走 Vite dev server 代理绕开
   （同源相对路径），生产构建如实失败。`proxyUrlFor` 统一维护代理前缀表。
4. **所有 fetch 必须带超时兜底**：浏览器原生 fetch 没有超时，上游偶发挂起会永久 pending，
   页面卡死在"无数据也无错误"。统一 `fetchKlinesWithTimeout`（默认 12s，可传参）。
5. **图表库差异一律查本文 2 节**，别凭直觉调 API——4 个库的接入方式差异巨大，且都有专坑。
6. **测试前置**：Playwright 冒烟测试要求 dev server 已在 5173 运行；调试用一次性探针脚本
   `tests/probe-*.mjs`（`npx tsx` 跑，用完即删）。

## 1. 数据源层（5 源接入实战）

### 1.1 各源坑位与解法

| 源 | 主要坑 | 解法 |
|---|---|---|
| **Binance** | `api.binance.com` 大陆直连不通（连接超时） | 用同构公共端点 `data-api.binance.vision`（S3 加速域名，无需 key，返回结构一致）；返回本就时间正序，无需 sort |
| **腾讯财经** | ①分钟 K 用 `ifzq.gtimg.cn`（不是 `web.ifzq`，后者对分钟接口 301）；②日线指数返回 `day` 键、股票返回 `qfqday` 键；③**4h=m240 实测 `param error`**，腾讯原生不提供 4h → 不暴露为支持周期；④实时接口 GBK 编码（浏览器按 charset 自动解） | 三接口各司其职（日线 fqkline/get · 分钟 mkline · 实时 qt.gtimg.cn）；周期映射 1m→m1、5m→m5、15m→m15、1h→m60、4h→m240、1d→day；只支持 A 股 sh/sz 前缀代码 |
| **东财** | ①**DNS 坏池**：`push2his` 被解析到 trafficmanager.cn 的坏 IP 池，K 线请求直接 reset（Empty reply）；②4h 无原生（分钟只到 60）→ 用 60 近似但**不作为支持周期暴露**；③搜索 suggest JSONP 用 `cb` 回调参数 | Vite dev server 的 `/push2his` 代理直连好池 IP（显式 SNI + Host，见 vite.config.ts）；klt 映射 1m→1、5m→5、15m→15、1h→60、4h→60、1d→101；secid 规则 sh→1.x、sz→0.x |
| **Twelve Data** | ①免费层 8 credits/分、800 credits/天，demo key 同样限频，快打 429；②`datetime` 是交易所本地时区、无时区后缀；③返回新→旧倒序 | 显式按本地时间拆分解析（见总纲 2，但注意**这源按本地时间**而非 UTC——分钟线本地时区解析与图表本地时间轴一致即可）；demo key 或 `.env` 的 `VITE_TWELVEDATA_KEY`；直连带 `Access-Control-Allow-Origin: *`，无需代理 |
| **Yahoo Finance** | ①**无 CORS 头**，浏览器直连被拦；②**无服务端 limit 参数**，返回行数由 period1/period2 时间窗决定；③反爬 429 限流；④停牌/缺数据段字段为 null；⑤时间戳是**秒**须 ×1000 | `/yh` 代理；时间窗按「limit 根 × 每周期日密度 × 1.5 余量」缩放（`windowMs`），轮询（limit=2）窗口自动收窄省流量；null 字段跳过；`barsPerCalendarDay` 密度表（1m 390、5m 78、15m 26、1h 6.5、4h 2、1d 5/7） |

### 1.2 可复用模式（src/data/ 下，新项目直接搬）

- **`fetchWithTimeout.ts`**：`fetchKlinesWithTimeout(input, init?, timeoutMs=12000)`，
  AbortController + setTimeout + `.finally(clearTimeout)`。5 源 K 线请求 + 连通性检测全部经它。
- **`connectivity.ts`**：`proxyUrlFor(url)` 在 dev 下把需代理源站 URL 换成 Vite proxy 前缀路径
  （`query1.finance.yahoo.com→/yh`、`api.kraken.com→/kr`、`api.fund.eastmoney.com→/ttjj`、
  `www.shfe.com.cn→/shfe`、`push2his.eastmoney.com→/push2his`）。代理前缀表**只维护这一份**，
  vite.config.ts 的 proxy/中间件挂对应前缀——加新源只改两处（proxyUrlFor 表 + vite.config）。
- **`normalizeKlines.ts`**：`normalizeKlines(bars, limit)` = 按 time 升序 sort + `slice(-limit)`。
  各源返回顺序不一（腾讯/东财/Yahoo 倒序、Twelve Data 新→旧倒序、Binance 正序），统一收尾。
- **`pollSubscribe.ts`**：2s 轮询最新 1~2 根模拟实时订阅，5 源共用。注意轮询+历史请求并发
  可能触发限频（Yahoo 429 / Twelve Data 429），失败静默忽略下一轮重试。
- **JSONP 两种模式**（`aShareSearch.ts`）：
  - **回调型（东财 suggest）**：服务端拿 `cb` 回调参数回填回调名再调用。**必须先落全局回调再设
    `el.src`**（反之极快网络下回调先于 `window[cbName]` 赋值执行 → ReferenceError）；cleanup 把
    回调改成 **no-op 而不是 delete**（东财偶发 script 200 但执行被推迟到超时后，delete 会让迟到
    回调抛 ReferenceError 被测试计为 pageerror）。
  - **全局变量型（腾讯 smartbox）**：**不认任何回调参数**，响应体是 `v_hint="..."` 全局赋值脚本。
    正确取法：onload（script 已同步执行完）后读 `window.v_hint`，读完整理现场（恢复旧值、移除 script）。
  - **双源竞速**：首成功即胜（`new Promise` 天然只收第一个 resolve）+ 计数器法——每源自带超时
    （东财 5s / 腾讯 4s）保证必然落定，双败时最后一个落定的源立即 reject，**不要挂全局超时干等**
    （旧实现 9s 全局兜底是浪费）。

## 2. 图表库层（4 库接入实战，每库都有专坑）

> 统一做法：OHLCV 毫秒时间戳进各库前先转库内格式，各库的 `toXxx` 转换函数放组件内。

### 2.1 Lightweight-Charts

- **`UTCTimestamp` 是秒，OHLCV.time 是毫秒** → `toCandle`/`toVolume` 必须 `/1000`，
  否则日期漂到 57647 年。
- 增量：按 `lastTimeRef` 判断整体替换或逐根追加（`setData` 全量 / `update()` 增量）；
  **增量起点找不到（竞态/整体重置）要退化全量**。
- `layout.attributionLogo: false` 去掉左下角 TradingView logo（已按库 NOTICE 在代码注释保留声明）。

### 2.2 klinecharts v10（坑最多）

- **v10 没有 `applyNewData`/`updateData`**——别去找公共增量接口，只能用 `setDataLoader`。
  - `getBars('init')` 全量投喂；实时增量经 `subscribeBar` 回调注入单根 bar，
    内部 `_addData('update')` 自动追加/替换。
  - **`setDataLoader` 只能注册一次**（mount effect 里，依赖 `[]`）。
- **`createIndicator` 每次调用都新建副图 pane 不去重** → 必须用 ref 防重
  （`volCreatedRef`），否则轮询反复调用会累积多个 VOL 窗口把主图挤成 0 高。
- **`setSymbol` 必须调用**（真实回归 bug）：`_symbol` 初始为 null，只更新组件侧 symbolRef
  而跳过 `chart.setSymbol()`，切标后库内部 `_symbol` 停在初始值，`getBars` 的防错投喂检查
  （`symbolRef.current !== params.symbol.ticker` → 返回空）会把新请求判成"错标"，**图表空白**。
  `setSymbol` 内部会 resetData → 触发 getBars('init') 重新投喂，并同步库内 symbol 状态。
- **副图 pane 高度是固定像素而非比例**：主图拿剩余高度。要让主图:副图恒为 7:3，
  反算 `H_vol = round((容器高 − x轴高) ÷ (1 + 7/3))`，init 时用默认 x 轴高 26px 估算，
  ResizeObserver 监听容器高度变化后用 `setPaneOptions` 重算（库内部自带 ResizeObserver 只重排
  不按比例，必须自己监听）。
- **period 对象是父级每次渲染新建的**：effect 依赖只用 `period.type/period.span` 两个原语，
  否则父级每次 setState（状态条/操作提示）都触发子组件 effect 重跑 → resetData → 图表库吐
  `onVisibleRangeChange` → 父级又 setState 的**同步无限循环**。
- `registerIndicator`/`registerOverlay`/`registerHotkey` 是**全局单例**，只注册一次；v10 自定义
  指标用 `figures`（不是 v9 的 `plots`）。
- 数据时序：父级切换会先 `setHistory([])` 再拉新数据，但**清空发生在子组件 effect 之后**——
  子组件用 `loadedKeyRef`（`symbol/period` key）判断增量 or 全量重载，空数据到达时清 key，
  `data` effect 里 data.length===0 时只清 key 不立即 resetData（会读到旧 dataRef）。

### 2.3 HQChart

- 数据接入：`NetworkFilter` 拦截内置 HTTP 请求（RequestHistoryData / ReqeustHistoryMinuteData），
  `PreventDefault` 后回调注入数据；实时用 `ManualUpdateKData` 推送。
- **`ChartDestroy()` 只清内部实例、不清理 DOM**；开发态 StrictMode 双挂载会叠出第二个实例画到
  容器外 → mount effect 的 cleanup 必须移除库生成的 `.jschart-drawing*` / `.jschart-tooltip` /
  `.UMyChart_*` 节点。
- **`ManualUpdateKData` 必须显式传 `DataOffset`**，否则 `newDataCount` 恒为 0，视图冻结在最旧一侧。
- `NetworkFilter` 里对流股本（RequestFlowCapitalData）置 PreventDefault，否则库内兜底请求
  `127.0.0.1:8080` 产生 console error（测试计为 pageerror）。
- **周期常量不一致**：HQChart Period 是 0/4/5/6/8/12（日/1m/5m/15m/1h/4h），需要映射。

### 2.4 ECharts

- 类型只能从 `echarts/types/dist/shared` 导入（`XAXisOption` 等，type-only 不产生运行时代码，
  不影响按需打包）。
- `setOption` 全量用 `notMerge` 替换；增量靠默认 merge 语义逐系列更新；category 轴增量时
  `data` 要跟着推进。
- 各库统一约定：`data[last].time` 倒退或首次加载 → 全量重设，据此判断整体替换 vs 增量追加。

## 3. React 工程层

- **StrictMode 双跑 mount effect**：任何图表库初始化如果 cleanup 不彻底会叠出第二个实例。
  轻量方案：cleanup 里清理库生成的全部 DOM 子节点（HQChart 就是这么修的）。
- **切页卸载/重挂载**：对比看板切走即停止轮询（数据保鲜），切回重新拉取。筛选状态（数据源/
  标的/周期/实时/根数）**提升到 App 全局持有 + localStorage 持久化**（`loadChartViewState` 校验
  结构，异常当无存档；仅恢复时归一化周期，会话中不钳制用户/测试选的值）。
- **`useKlineData` 模式**（三页共用数据流）：拉历史 + 订阅实时，返回 `{ history, error, retry }`。
  - 竞态守卫：effect 内 `cancelled` 标记丢弃过期响应；`historyLoaded` 置位前收到的实时推送直接丢弃
    （订阅轮询可能比历史先返回"最新一根未收 K 线"，避免首屏只剩 1 根）。
  - `retry()` 用自增计数加入 effect 依赖，放弃旧请求按当前参数重拉。
  - **错误语义**：error 保持 null 且 history 为空 = "加载中"或 fetch 被挂起；不支持周期会 throw →
    error 非 null → 走错误面板而非"周期不受支持"警告。页面据此推导警告窗口期，无需单独 loaded state。
- **轮询订阅竞态**：`subscribe()` 返回 unsubscribe，内部 generation 守卫丢弃过期响应（pollSubscribe）。
- **子组件拿最新数据用 ref，不能用闭包**：父级清空 history 发生在子组件 effect 之后，异步回调
  （getBars/状态条回调）必须从 ref 读最新值，闭包会捕获过期值。

## 4. 测试与调试

- **前置**：Playwright 冒烟测试要求 dev server 已在 5173 运行（`npm run dev &` 再 `npx playwright test`）。
- **3 个 spec**：`dashboard.spec.ts`（4 库渲染、bars ≥ 250、切换同步刷新、无 error-panel/pageerror）、
  `showcase.spec.ts`（两个详页大图 + 功能开关）、`datareport.spec.ts`（数据调研页 + 一键检测，
  **只跑单个文件**）。dev server 确认 200 后可只跑相关文件。
- **探针脚本**：`tests/probe-*.mjs` + `npx tsx` 直接跑（可开页面、读 canvas 像素、查 DOM），
  用完即删。CLAUDE.md 调试技巧有说明。
- **测试能守住的关键流程**：`showWarn` 警告流程用 `page.route` 把东财请求挂起（不 resolve 不
  reject，error 恒 null）来测——模拟"加载中/被挂起"窗口。写类似测试可直接照抄这个手法。
- **常见失败根因**：某库适配又触发"多实例/多 pane"（查 canvas 数量、`.bars-count` 文本）。
- 静态调研页改动只需 `tsc` + 对应冒烟测试；纯文档改动无需测试。

## 5. 给下一个更大项目的起步清单

**架构**（照抄，能省一半坑）：
1. 数据源适配器 / 图表库适配器 / 页面三层分离，中间只认 `OHLCV` 协议（毫秒时间戳）。
2. `fetchKlinesWithTimeout` + `proxyUrlFor` + `normalizeKlines` + `pollSubscribe` 四个模式直接搬。
3. 时区方案开工第一天就定死：fake-UTC（上游壁钟串按 UTC 构造 + 图表按 UTC 渲染）。
4. 新增数据源 = 实现 `KlineDataSource` 接口（fetchKlines/subscribe/searchSymbols）+ 注册表登记
   + proxyUrlFor/vite.config 各加一行（若需代理）。
5. 新增图表库 = 实现统一 props（data/symbol/period/live）+ resetKey，先过 4 库冒烟再扩展功能。

**决策备忘**：
- 原生 fetch 无超时 → 所有请求走超时封装，兜底值要盖过慢源又要保证测试窗口内落定。
- JSONP 双源竞速用"首成功即胜 + 计数器法"，别挂全局超时。
- 图表库 v10 类的新版（重写 API）尤其要先查"有没有增量接口 / 注册防重 / 内部状态同步"，
  这三类是踩坑重灾区。
- 浏览器直连有 CORS/坏池/反爬的源，dev 代理方案是标配；生产环境如实失败要写进文档预期。
