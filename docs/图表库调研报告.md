## 二、四大候选库详细对比（首批接入）

### 1. TradingView lightweight-charts ⭐ 首选

> 行业事实标准，金融图表的"教科书"级实现。

**优点**
- 专业金融图表范式：时间戳索引、OHLCV series 体系、数量缩放、平移/缩放、十字光标、价格刻度
- 极小的包体、零依赖，启动/渲染性能一流
- v5 插件体系成熟（自定义指标、画笔、叠加层），官方给出交互式插件示例
- 数据接入规范清晰，是各数据源适配的最佳"规范定义者"
- 声明式 API 直观，学习成本低
- 社区庞大，React/Vue/Svelte 封装齐全

**缺点**
- 无内置技术指标与画线工具（需插件/自行实现）
- 不内置数据源/交易所适配，需自建数据层
- 主题定制能力中等（不如图表全功能库）

**最适合**：证券/加密/期货等专业行情展示；需要稳定性能与规范数据流的中大型产品。

---

### 2. klinecharts / KLineChart ⭐ 开箱即用

> 中文生态最优秀的轻量 K 线库，"零依赖 + 开箱即用"。

**优点**
- 开箱即用：内置 20+ 技术指标（MA/BOLL/MACD/KDJ…）、画线工具、周期切换
- 零第三方依赖，gzip 后仅 ~40kb，移动端友好
- 中文文档完善，类型定义完整（TypeScript）
- 富样式配置与 API，可扩展性强（可注册自定义指标/图形）
- 周期/指标/画线一键切换，功能覆盖完整

**缺点**
- 社区规模与生态小于 TradingView
- 非通用图表库，画不了常规业务图表
- 缺少 v5 插件那种官方扩展市场

**最适合**：A股/数字货币产品；需要开箱即用功能（指标/画线/移动端）的场景。

---

### 3. HQChart ⭐ 多市场综合

> 国内老牌多市场 K 线图库，覆盖 A股/港股/美股/期货/数字货币。

**优点**
- 多市场覆盖：沪深/港股/数字货币/期货/美股
- 通达信语法、麦语言指标脚本支持（对量化人群友好）
- 内置画图工具、截图、筹码图、走势图、十字光标
- 第 3 方数据替换接口，易接入国内数据源（如 tushare）
- H5 + 微信小程序双端支持
- 国内行情/交易习惯理解最深

**缺点**
- 文档与代码注释以中文为主，国际化弱
- API 设计较"重"，学习曲线比 lightweight-charts 陡
- 社区规模中等

**最适合**：A股/港股/期货等国内场景；需要通达信/麦语言脚本、筹码图等特色功能的产品。

---

### 4. Apache ECharts ⭐ 全能对照

> 通用图表库之王，K 线只是其上百种图表之一。

**优点**
- 67.3k★，生态/社区/文档(中英) 一流，Apache 基金会背书
- 一套库通吃所有图表（K线/折线/饼图/仪表盘/地图…），大型看板可能一个库全覆盖
- Canvas + SVG 双渲染；大数据量性能优秀
- 声明式 option 配置 + 事件体系，主题定制能力强

**缺点**
- 为通用而生，金融专业能力弱：K 线缩放/十字光标体验、OHLC 交互细节不如专业 K 线库
- 内置指标/画线工具需手动实现
- 包体积大（按需引入可缓解）

**最适合**：混合型看板（既有 K 线又有大量业务图表）；需要"一个库解决全部可视化"的场景。

## 五、适合大型看板软件的**技术路线建议**

> 目标：多图表同屏、多数据源接入、实时刷新、长期可维护。

### 结论先行

**主库选 lightweight-charts，辅以 KLineChart 作功能补充，ECharts 兜底通用图表。** HQChart 视目标市场决定是否接入（面向 A 股/期货必入）。

### 分层架构

```
┌─────────────────────────────────────────────────┐
│                   对比壳层 UI                    │
│   看板布局 / 主题 / 指标切换 / 数据源切换 / 交互   │
├─────────────────────────────────────────────────┤
│          图表适配层 (React 组件封装)              │
│   LW 适配器 │ KLine 适配器 │ ECharts 适配器       │
│        统一 props: { series, options }           │
├─────────────────────────────────────────────────┤
│          数据源适配层 (统一 OHLCV 接口)           │
│   Binance │ 交易所聚合 │ 自建模拟 │ 未来扩展       │
├─────────────────────────────────────────────────┤
│                 协议: 标准 OHLCV                 │
│    { time: number, open, high, low, close, v }  │
└─────────────────────────────────────────────────┘
```

### 为什么这么选

1. **lightweight-charts 做主轴** —— 它是金融图表的数据/交互规范事实标准，性能与体积最适合大型看板常驻多图场景；大看板最怕的是"图一多就卡"，它的 Canvas + 零依赖设计在这方面最稳。
2. **KLineChart 做功能补充** —— 需要开箱即用的指标、画线、移动端时直接换适配器即可，零成本横向对比。
3. **ECharts 兜底** —— 看板上不可避免还有折线/饼图/仪表盘等业务图表，用 ECharts 一个库解决，避免每个需求引一个新库。
4. **数据源与图表解耦** —— 统一 `OHLCV` 协议 + 适配层，后续接 Binance/其他行情源/自建回测数据都只是新增一个 adapter，不动图表层。
5. **HQChart 按市场定** —— 目标市场是 A 股/港股/期货时必入（通达信脚本、筹码图独有）；纯加密/海外场景可暂缓。

### 落地要点

- 每个库一个独立 React 组件，props 收敛到 `{ series: OHLCV[], options: Partial<T> }`
- 数据源用统一 `fetchKlines()` 接口，返回标准 OHLCV，内部缓存 + 增量更新
- 实时刷新用 WebSocket，数据层统一推送到各图表的适配器
- 主题令牌（token）化，四库共用一套配色变量，保证看板视觉一致
- 看板级性能：虚拟化渲染可见区、节流重绘、图表实例复用
